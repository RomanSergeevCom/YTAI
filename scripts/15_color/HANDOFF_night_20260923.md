## 2. ⛔ НАЙДЕНО АУДИТОМ, НЕ ПОЧИНЕНО

Девять находок, каждая воспроизведена скептиком руками. Чинить — следующей сессии.
Порядок по цене.

### 2.1 Витрина не сохраняет клики по экспозиции — ПОДТВЕРЖДЕНО живым прогоном

`persist()` зовётся только в ветке проявки/look. Прогон настоящего скрипта страницы
со стабами DOM:

```
кликов по экспозиции: 162 · в памяти изменено: 162 · в localStorage легло: 3
после перезагрузки: вернулось к машинному 162 из 162
```

Страница при этом пишет «восстановлен выбор от …». То есть человек правит день,
перезагружает вкладку — и правки молча исчезают, а надпись уверяет, что всё на месте.
**Сегодняшний выбор не пострадал** (`color_choice.json` содержит все 162), но
повторить эту удачу нельзя. JS-тестов у витрины нет вовсе.

### 2.2 Профиль канала можно снести целиком — ПОДТВЕРЖДЕНО

`save_choice` перезаписывает `YTs/{КАНАЛ}/color_profile.json` **без `backup()`**.
Если файл нечитаем, `load_json_safe` вернёт `{}`, и сохранение из ЛЮБОГО проекта
канала обнулит проявки, look и выученную цель — для всех проектов канала сразу.

⚠️ Триггер не теоретический: **файл лежит под git**. Маркеры конфликта от
merge/rebase/`stash pop` делают его нечитаемым. `backup()` живёт в том же модуле и
применяется к производному `color_plan.json`, а к невосстановимой ДНК канала — нет.
Тестов на `save_choice` нет ни одного.

### 2.3 Чужой файл фидбека зануляет день — ПОДТВЕРЖДЕНО

`save_choice` делает `doc.update(...)` без проверки `type`/`schema`, поэтому payload
старого формата кладёт `None` в `exposure`, `corrected`, `develop`, `machine` —
и поднимает `doc_version`. Форма существует: архивный подборщик
`_archive/lut_pick.20260922_232152.pre_3stage.py.bak:883` выгружал ровно
`{type: 'lut_feedback', choices, notes}` без этих полей.

### 2.4 Защита от совпадения basename не срабатывает у настоящего вызывающего — ПОДТВЕРЖДЕНО

Это **недоделанная моя же ночная правка**. Страж в `seed_gamma_cache_from_lut_plan`
проверяет словарь, который реальный вызывающий (`color_apply.build`) не строит.
Воспроизведение: клип DJI в `03_Office` получил гамму **Sony**, отказа не было.
`scene_clips` ловит дубли только ВНУТРИ сцены, между сценами — нет.
Спит: на YTEVO03 дублей basename нет.

### 2.5 Кэш гамм переписывается целиком, без слияния и без копии — ПОДТВЕРЖДЕНО

Переименовали сцену → запись о клипе пропала (6 → 5), бэкапов нет.

### 2.6 Сохранённая ступень вне показанной лестницы — ПОДТВЕРЖДЕНО, 17 строк из 162

Когда лица нет (`HAVE_VISION=False` или кадр без лица), `miss = None`, лестница
базовая ±1, но сохранённая ступень всё равно проставляется. На живом файле выбора
**17 строк**, где ни один показанный кадр не подписан «твой выбор», включая
`12_Site_Blessing_RYA_ZVE1_1932` с `+2.5 → +6,00` в Lumetri.
⚠️ Объяснение «сменили look» неверно: проб-кадр снимается только через проявку,
look в цепочку не входит.

### 2.7 `save_choice` пишет два файла подряд без транзакции — ПОДТВЕРЖДЕНО

Профиль канала первым, выбор дня вторым. Падение между ними оставляет половину.
Гонка четырёх процессов дала **333 падения** `FileNotFoundError` на `os.replace`
(общее имя временного файла). Битого JSON не получилось ни разу.

### 2.8 План может адресовать непроверенный куб — ПОДТВЕРЖДЕНО

При `--allow-refused` `cube_block` возвращает блок, даже если sha256 разошлась.
Смягчение: `--install` потом пересчитает sha и умрёт с кодом 4, то есть не молча.

### 2.9 NaN в JSON — ОПРОВЕРГНУТО

`json.loads` читает `NaN` штатно, а `JSON.stringify` его не выгружает. Цепочки нет.

⚠️ **Линза «логика» осталась без состязательной проверки** — агент упёрся в лимит
сессии. Её находки не подтверждены и не опровергнуты.

## 3. РЕШЕНИЕ ПО UXP (спроектировано, не реализовано)

Победил подход **«донор на проявку»**, но в уточнённой форме: **три слоя на клип**,
а не один.

```
клип (V1)
 ├─ проявка    клон донора, в Lumetri ТОЛЬКО Input LUT
 ├─ экспозиция ЧИСЛО по API в тот же Lumetri (или отдельный клон, если API не даст)
 └─ покраска   клон донора look, один длинный слой на слитые диапазоны плана
```

Почему look отдельным слоем, а не запечён в донор проявки: при отказе API экспозиция
приедет отдельным слоем **сверху**, то есть ПОСЛЕ покраски — а это не тот порядок,
что утверждал Роман. Разделив, получаем один комплект доноров для обоих исходов
пробы, и ручная работа не переделывается. Побочно: look меняется одной перепиковкой.

Ключевые решения:
- имя секвенции **новое** — `YTAI_COLOR_DONOR`; `YTAI_LUT_DONOR` не трогать, иначе
  сданные проекты поколения 1 начнут чехарду с переимпортом на каждом Apply;
- имена донор-клипов **из данных** (`install_name` без расширения), не из константы;
- слой покраски кладётся на **объединение диапазонов клипов плана**, иначе покрасятся
  титры, графика и тот самый Rec.709-клип, который план осознанно пропустил;
- ⚠️ три Lumetri подряд эквивалентны одному **только в 32-битном float** — на
  софтверном рендере `+6 EV` клипнется до покраски. Нужен «Maximum Bit Depth».

### Новый дефект в существующем коде панели, найденный при проектировании

`adjustmentBuilder.js:521` — `verified = (postInner === paramValue)`. Premiere хранит
float32, и `1.2` возвращается как `1.2000000476837158`: строгое равенство **ложно**.
Спасает только второе условие `postInner !== preInner`, а оно ложно при повторной
записи того же значения (лечение, повторный прогон). Для экспозиции нужен допуск.

## 4. ПРОБА PREMIERE — 15 МИНУТ, ТОЛЬКО РОМАН

Кубы уже лежат. ⚠️ Если Premiere был открыт — **перезапустить**: список читается при старте.

1. Открыть YTEVO03. Сделать руками adjustment layer над клипом, добавить Lumetri.
2. Поставить **Basic Correction → Input LUT** = `YTAI_sony__slog3…legacy`,
   **Exposure** = `+1.5`, **Creative → Look** = `YTAI_look__newstar`.
3. Назвать слой `YTAI_PROBE_HAND`. Это эталон — самые ценные 4 минуты.
4. Нажать пробу (кнопка ещё не написана), ⌘Z, **не сохранять**.

Что проба обязана ответить **данными**, а не словами: дамп ВСЕХ параметров по индексу
и пары «до/после» на каждую запись. Отсутствие исключения доказательством не считается.

⚠️ `setEffectParam` матчит по имени и берёт **последнее** совпадение. У Lumetri имена
дублируются (`Look` 34 и 35, `Input LUT` 6 и 7, `Saturation` ×4), поэтому вердикт
18.08 «Look мёртв» мерил индекс 35, а **34 не трогали ни разу**. Адресоваться по индексу.

Прогноз по форме: `Exposure` (индекс 19, уникальный float ±7) скорее ставится —
он как `Position` у Motion, который панель уже умеет. `Input LUT` скорее нет.
