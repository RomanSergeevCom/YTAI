# 15_color — цвет: проявочные и покрасочные луты

**Сквозной слой, вызывается по требованию.** НЕ часть линейного `run_pipeline` —
как `11_sync`, `12_acquire`, `14_media`. Цвет нужен и на ингесте, и на прокси,
и на сдаче, поэтому он не принадлежит монтажу и не живёт в `05_editing`.

## Зачем слой появился

До сентября 2026 цвет был **одной ступенью**: три куба
(`01_bright_scene` / `02_normal_scene` / `03_dark_scene`), в которых проявка
(log → Rec.709) и покраска слиты в один файл, и все три сделаны под S-Log3.
Снятое в другой гамме красилось чужой математикой: на съёмочном дне YTEVO03
это 61 клип DJI Pocket 4 Pro из 163 — **37 % дня**.

Замер 22.09 показал, в чём именно вред: S-Log3-лут на материале D-Log2 не
«обесцвечивает», как считалось, а **топит экспозицию** — luma 58 → 23, 80 → 47.
Это же объясняло вырождение подборщика: счёт «яркость + насыщенность» видел
утопленные кадры как тёмные и ставил им лут, который вытягивает.

## Три ступени

```
исходник в LOG
   │
   ├─ 1. PRE-LUT (необязательно) ── буст динамического диапазона
   │
   ├─ 2. ПРОЯВОЧНЫЙ ── log → Rec.709, ПО КАМЕРЕ И ГАММЕ.
   │      Технический шаг. Выбирается детерминированно из метаданных клипа.
   │
   └─ 3. ПОКРАСОЧНЫЙ ── look поверх нормальной картинки.
          ДНК канала. Один на канал, выбирает человек.
```

## Команды

```bash
V=~/YTAI/environment/.venv_vlm/bin/python3
L=~/YTAI/scripts/15_color/1501_lut_library/lut_lib.py

$V $L --import                 # сухой прогон, печатает что БЫ сделал
$V $L --import --apply         # наполнить store/ из ~/Downloads/Luts
$V $L --validate --deep        # проверить store и манифест, посчитать метрики
$V $L --list --stage develop   # показать библиотеку
$V $L --legacy --apply         # архив старых кубов канала с атрибуцией
$V $L --sync --push --apply    # зеркало store → Shared Drive YTAI
```

Без `--apply` ничего не записывается. Ни один режим не пишет в `~/Downloads/Luts`.

лежат 12 кубов — шаблоны папок проектов и бандл UXP-плагина.

## Грабли

- ⚠️ **Имя файла — не доказательство.** `DJI Action basic.cube` внутри содержит
  `# Mavic 3 Pro, D-Log M` — имя врёт про камеру, и байт-в-байт тот же файл лежит
  как `DJI OSMO Osmo Nano D-Log M.cube`. Модель принимается, только если её
  подтверждает комментарий внутри куба или человек.
- ⚠️ **Верхняя папка коллекции называется «Проявочные LUTs для LOG (sony, canon,
  panasonic, apple)»** — поиск вендора по полному пути пометит все панасониковские
  кубы как Canon. Искать только по имени zip и внутреннему пути.
- ⚠️ **Pre-LUT в коллекции физически один**: 7 копий под именами Dji / Slog2 /
  Slog3 / Pocket 4 байт-в-байт идентичны. Имена врут про вендора.
- ⚠️ **Два диалекта `.cube`**: Resolve (пробелы, LF) и LUT Editor (**ТАБ** после
  `LUT_3D_SIZE`, CRLF, без TITLE). `line.split()` без аргумента ест оба.
- ⚠️ **В `.cube` быстрее всего меняется КРАСНЫЙ**: `reshape(N,N,N,3)` даёт
  индексацию `[b,g,r]`. Перепутать — получить куб, который переставляет каналы
  в тенях и на глаз ловится не сразу. `cube.selftest()` это проверяет.
- ⚠️ **Один zip-вход со снятым UTF-8-флагом**: `DJI Pocket 4р D-Log Ocean.cube`
  (кириллическая `р` вместо латинской `P`). `unzip` даст мохибейк `4╤Ç`; лечится
  `name.encode('cp437').decode('utf-8')`. Файл — точный дубль, схлопывается.
- ⚠️ **AppleDouble `._*.cube` внутри архивов** имеют собственные sha256 и без
  фильтра по префиксу заводят фантомные записи.
- ⚠️ **Имена папок на macOS в NFD** (`Серёжи` = `е` + U+0308). Любое сравнение —
  после `unicodedata.normalize('NFC', …)`.
- ⚠️ **Автоклассификатор ступени отвергнут** как решающий — см.
  `project_knowledge/stage_detect_calibration.md`. Ступень берётся из папки-источника,
  метрики работают только флагом на проверку человеком.
- ⚠️ **Серый клин не заменяет реальные кадры.** Пара DJI `D-Log2 +/−` различается
  на клине на 3 пункта, а на материале дня — на 23. Клин отбирает кандидатов,
  решают кадры в витрине.

KB: 3.8 `/kb/luts/` (перепишется под три ступени).
