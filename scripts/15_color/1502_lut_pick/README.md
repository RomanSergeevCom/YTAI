# 1502_lut_pick — витрина выбора цвета

Этап **решения**: показать человеку его собственный съёмочный день, прогнанный
через кандидатов, и записать выбор. Ничего не кладёт на таймлайн — раскладку
собирает `1503_color_apply` из того, что здесь подписано.

Порядок на странице — **порядок РЕШЕНИЙ**, а не обработки: сначала две настройки
на весь канал (проявка, покраска), и только потом экспозиция по клипам под ними.
Выбирать экспозицию, не зная look, бессмысленно — он двигает яркость.

```bash
V=~/YTAI/environment/.venv_vlm/bin/python3
B=~/YTAI/scripts/15_color/1502_lut_pick/lut_board.py

$V $B --project "/Volumes/T9-Black-RYA/YTEVO/YTEVO03_Plechko_day" \
      --frames-from ~/Desktop/YTEVO03_01_Source_Proxy --jobs 6

$V $B --project "<путь>" --feedback <файл.json>   # сохранить выбор и выйти
```

Выход в `{проект}/01_Source/00_LUT/_build/` — дом лутов, этаж «как выбирали»
(наверху, плоско, лежат только рабочие кубы; файлы проектов, собранных до
переезда, читаются из старого `00_Setup/01_Ingest/` и об этом говорится в логе):

- `{CODE}_lut_board.html` + `_files/` — витрина на кадрах дня;
- `{CODE}_color_choice.json` — выбор: проявка по камерам, look, экспозиция по клипам,
  плюс блок `stage`, которым файл описывает сам себя;
- ДНК канала уезжает в `YTs/{КАНАЛ}/color_profile.json`.

## Файлы

```
lut_board.py     витрина: кадры → страница → сохранение выбора
color_media.py   клипы, пути, гамма            — ТОЛЬКО stdlib
color_frames.py  кадры, метрики, лица          — numpy/PIL, Vision опционально
color_plan.py    экспозиция, ключи, профиль    — ТОЛЬКО stdlib
_archive/        прошлые поколения подборщика, как документ замеров
```

Отбор кандидатов из библиотеки живёт этажом выше — `1501_lut_library/lut_select.py`.

⚠️ **Разделение на модули — не косметика.** `color_media` и `color_plan` обязаны
работать **без ffmpeg, без Vision и с размонтированной картой**: раскладка
(`1503_color_apply`) собирается из двух JSON, и тащить туда numpy незачем.

## Грабли

- ⚠️ **Стоп витрины ≠ стоп Lumetri, множитель 2,4.** Превью считает экспозицию
  фильтром ffmpeg **поверх гамма-кодированного Rec.709** — умножение кода на `2^X`
  (замерено: код 64 при `+1 EV` даёт 128). Lumetri линеаризует **до** экспозиции
  (`LUT → Linearize Gamma 2.4 to Linear → BasicCorrection3`), и тот же `+1` дал бы ≈85.
  Пересчёт — `color_plan.to_lumetri_stops`, предел слайдера ±7 проверяет
  `check_lumetri_stops`. Кадры, которые человек утверждал, **верны как изображение**;
  расходится только число.
- ⚠️ **Незнакомая гамма — отказ, а не «mismatch и поехали».** Ровно эта
  снисходительность покрасила 61 клип DJI из 163 чужой математикой.
- ⚠️ **Замер лица — только на проявленном кадре.** На логе «кожа ≈ 150» не значит
  ничего: лог кодирует 18 % серого около 0,41. Рамка лица ищется один раз, на кадре
  0 стопов, и передаётся во все ступени лестницы.
- ⚠️ **Имя кадра обязано нести всё, от чего зависит содержимое** — проявку, look и
  стоп. Трижды за одну сессию кадры переживали смену рекомендации и подписывались
  чужим кубом; один раз вся экспозиция по 163 клипам считалась по логарифмическим
  кадрам, потому что имя не несло проявку.
- ⚠️ **Слаг клипа лоссовый и вшит в ~1100 имён кадров.** `clip_slug` менять нельзя —
  это перерендер всего дня. Канонический ключ — `clip_key` вида `сцена/клип.MP4`,
  его же читает панель UXP.
- ⚠️ `frame_ok` заменил старый `jpeg_ok`: порог 4 КБ был откалиброван под 960 px и
  браковал нормальные проб-кадры 320 px (они весят ~1,2 КБ). Вес JPEG зависит от
  детальности, а не от целости.
- ⚠️ **Серый клин не заменяет кадры дня.** Пара DJI `+`/`−` различается на клине на
  3 пункта, на материале — на 23.
