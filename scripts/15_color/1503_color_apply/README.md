# 1503_color_apply — раскладка цвета по клипам

Этап **применения**: превратить подписанный человеком выбор в план, который
кладут на таймлайн. Ничего не решает — только считает следствия из двух файлов.

```
{проект}/01_Source/00_LUT/_build/{CODE}_color_choice.json   выбор по ЭТОМУ дню
YTs/{КАНАЛ}/color_profile.json                               ДНК канала
                          ↓
{проект}/01_Source/00_LUT/_build/{CODE}_color_plan.json      раскладка
{проект}/01_Source/00_LUT/_build/{CODE}_gamma_cache.json     замер гамм
{проект}/01_Source/00_LUT/YTAI_{id}.cube                     кубы — ПЛОСКО, по --install
```

У лутов **один дом** — `{проект}/01_Source/00_LUT/`. Наверху лежат рабочие кубы,
чтобы монтажёр открыл папку и сразу увидел, чем красят; всё, по чему выбирали, —
этажом ниже, в `_build/`. Файлы проектов, собранных до переезда, читаются из
старого адреса `00_Setup/01_Ingest/` (об этом говорится в логе), но пишутся уже
только в новый. Там же и дальше живёт легаси `{CODE}_lut_plan.json`: его читает
UXP-панель, и он никуда не переезжает.

```bash
V=/opt/homebrew/bin/python3.11        # хватит любого python3: только stdlib
A=~/YTAI/scripts/15_color/1503_color_apply/color_apply.py

$V $A --project "<путь>"                  # сухой прогон, ничего не пишет
$V $A --project "<путь>" --apply          # записать план и кэш гамм
$V $A --project "<путь>" --verify         # сверить кубы со store по sha256
$V $A --project "<путь>" --allow-refused  # записать, несмотря на отказы
$V $A --project "<путь>" --install --apply  # кубы в папки Adobe И в 01_Source/00_LUT
```

⚠️ `--install` раскладывает кубы по ДВУМ адресам, и второй не дублирует первый:
в папки Adobe — чтобы их увидел Premiere **на этой машине**, в `01_Source/00_LUT`
проекта — чтобы они **уехали вместе с проектом**. Без второго шага монтажёру
уходит тройка из шаблона, то есть старый цвет под видом нового, и ни одного
сообщения об этом. Общая папка Adobe читается при СТАРТЕ Premiere — если он был
открыт, перезапустить.

## Почему отдельный файл, а не расширение `lut_plan.json`

В старом плане значение `plan[ключ]` — это **имя клипа-донора**, и панель кладёт
его прямо в имя слоя (`index.js` → `adjustmentBuilder.js`). Трём ступеням нужен
объект из трёх полей; положить объект туда — получить `[object Object]` в имени
Look. Плюс старый план — единственный источник гамм этого дня, пока карта не
примонтирована: перезаписать его значит уничтожить то, на чём день держится.

⚠️ **Ключ `plan` — `"сцена/клип.MP4"`, формат не менять.** Панель пере-ключует
его по basename. Проверено на YTEVO03: 162 ключа → 162 уникальных basename.

## Грабли

- ⚠️ **Экспозиция пересчитывается ×2,4.** Витрина считала её фильтром ffmpeg
  поверх гамма-кодированного Rec.709, Lumetri линеаризует **до** экспозиции.
  В документе лежат `exposure_units: stops_lumetri`, множитель и флаг
  `exposure_verified_against_premiere`. ⚠️ Пока флаг `false`, утверждать перенос
  один в один нельзя — множитель выведен из блоба шаблона, а не замерен.
- ⚠️ **Отказ громче тишины.** Непустой `refused` → файл **не пишется**, выход ≠ 0.
  Клип без слоя в Premiere выглядит как обычный клип; молча пропустить его хуже,
  чем не собрать план. Обойти — `--allow-refused`, осознанно.
- ⚠️ **Rec.709 — это `skipped`, а не отказ.** Клип не в логе, проявлять нечего.
  На YTEVO03 такой ровно один, и 162 из 163 — правильное число, не потеря.
- ⚠️ **Отбор сцен общий с витриной** (`color_media.content_scenes`): служебная
  `00_Tests_And_Sync` — не фильм. Два разных правила дали бы двум инструментам
  разные числа, и разбираться пришлось бы монтажёру.
- ⚠️ **Имя установки выводится из id, с префиксом `YTAI_`.** Lumetri ссылается на
  имя файла, а `look__newstar.cube` в общей Creative-папке — столкновение, ждущее
  своего часа. Переименовывать луты в сданных проектах нельзя никогда.
- ⚠️ **Общая папка Adobe читается при СТАРТЕ Premiere.** Копировать кубы нужно до
  запуска: панель изнутри программы уже опоздала.
- ⚠️ **Файл производный.** Руками не править — следующий `--apply` перезапишет.
  Что из чего собрано, записано в `sources` вместе с версиями входов.
