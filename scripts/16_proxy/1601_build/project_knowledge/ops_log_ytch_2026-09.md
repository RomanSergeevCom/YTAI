## 1. Зачем этот тикет

Прокси — это **лёгкая копия, а не мелкая**. Единственное, ради чего она делается, — вес файла.
Всё остальное обязано совпадать с оригиналом, потому что прокси должен подменяться на оригинал
**сменой одной корневой папки** (Premiere *Attach Proxies* / *Link Media*), без единого сдвига
по кадрам, звуку и таймкоду.

Повод: 22.09.2026 при сверке комплекта YTCH спринта 3 (441 прокси, собраны 17.08.2026) нашли
два дефекта.

**Дефект 1 — 8 бит на 10-битном S-Log3.** Исходники FX3 = `yuv422p10le`, прокси собраны
`yuv420p` / profile Main. Это не решение, а старый дефолт `make_proxies.py`, который был
исправлен уже после того прогона. Замер на том же материале (15 с, тот же битрейт 8 Мбит/с,
после наложения рабочего `02_normal_scene.cube`):

| Битность | Размер файла | Время кодирования | PSNR после LUT |
|---|---|---|---|
| 8 бит (main / yuv420p) | 15 238 245 Б | 4.9 с | 40.92 дБ, худший кадр 37.56 |
| 10 бит (main10 / p010le) | 15 232 028 Б | 4.6 с | **43.16 дБ**, худший кадр 39.50 |

Одинаковый размер, одинаковое время, **+2.24 дБ**. 8 бит платит ни за что — и платит именно
там, где видно: LUT растягивает лог обратно, банды лезут в небе, коже и градиентах.

**Дефект 2 — таймкод не доезжает.** Оригинал FX3 несёт tmcd-дорожку (`TAG:timecode=03:11:06:24`),
прокси её не несут — ни одного из 441. Проверено, что это чинится (см. §5).

## 2. Контракт: что обязано совпадать

Проверяется **на каждом клипе**, а не на выборке.

| # | Параметр | Правило | Чем проверять |
|---|---|---|---|
| 1 | Разрешение | 1:1 с источником. 3840×2160 остаётся 3840×2160, **не уменьшать** | `ffprobe stream=width,height` |
| 2 | fps | 1:1, **включая дробные**: 29.97 = `30000/1001` ≠ 30 | `ffprobe stream=r_frame_rate` |
| 3 | Число кадров | **Ровно то же.** Не «примерно», не по длительности | `ffprobe -count_packets` → `nb_read_packets` |
| 4 | Битность | **По источнику.** 10 бит → `main10` / `p010le`. 8 бит → `main` / `yuv420p`. Не повышать и не понижать | `ffprobe stream=pix_fmt,profile` |
| 5 | Имена и пути | Имя файла и относительный путь сцены — 1:1. Отличается только имя корневой папки | сверка относительных путей |
| 6 | Звуковые дорожки | Столько же и в том же порядке. **Каналы не схлопывать** — у камер L и R часто разные микрофоны | `ffprobe stream=codec_type,channels` |
| 7 | Таймкод | Перенести из tmcd источника | `ffprobe -select_streams d stream_tags=timecode` |
| 8 | Цветовые теги | Проносить из источника как есть. **Не форсить bt709 на логе** | `ffprobe stream=color_space,color_primaries,color_transfer` |

Отличаться имеет право **только это**:

- кодек и битрейт: HEVC ~8 Мбит/с вместо H.264 ~140 Мбит/с → ×17–18 по весу
- цветовая субдискретизация 4:2:2 → 4:2:0 (аппаратный кодер иначе не умеет; цвет всё равно
  тянется с оригинала, для оффлайна не цена)

## 4. Правило «не жать то, что уже лёгкое»

iPhone в комплект **копируется байт-в-байт**, не перекодируется — проверено на Drive:
`IMG_0393.MOV` 106 383 193 Б локально = 106 383 193 Б в прокси-комплекте. Материал уже
Rec.709, уже HEVC, уже лёгкий; перекодирование только портит.

⚠️ **Отдельная мина.** `IMG_0578.MOV` несёт 8 дорожек: видео, `aac` 2ch, **`apac` 4ch
(Apple spatial audio)** и пять `mebx`-метадорожек. ffmpeg `apac` не декодирует — попытка
пережать такой клип либо упадёт, либо молча потеряет дорожку и метаданные. Ещё одна причина
не трогать iPhone.

**Правило:** клип перекодируется, только если он тяжёлый лог-материал с камеры. Всё
остальное — `copy`. Если в клипе есть аудиодорожка, которую ffmpeg не декодирует, клип
**не перекодируется вообще** (ни одна дорожка не должна пропасть).

## 5. Эталонная команда

Параметры **читаются с источника** перед каждым клипом, не хардкодятся.

```bash
SRC="/path/to/RYA-FX3-1032.MP4"
DST="/path/to/proxy/RYA-FX3-1032.MP4"

# 1. снять параметры источника
TC=$(ffprobe -v error -select_streams d -show_entries stream_tags=timecode \
     -of csv=p=0 "$SRC" | head -1 | tr -d ',\r')
PIX=$(ffprobe -v error -select_streams v:0 -show_entries stream=pix_fmt \
     -of csv=p=0 "$SRC")

# 2. битность — по источнику
case "$PIX" in
  *10le|*10be|*12le) PROF=main10; OPIX=p010le ;;
  *)                 PROF=main;   OPIX=yuv420p ;;
esac

# 3. кодировать во временный файл (.part → мукcер задаём явно через -f mp4)
ffmpeg -y -v error -i "$SRC" \
  -map 0:v:0 -map "0:a?" \
  -c:v hevc_videotoolbox -b:v 8M -tag:v hvc1 \
  -profile:v "$PROF" -pix_fmt "$OPIX" \
  -c:a aac -b:a 256k \
  ${TC:+-timecode "$TC"} \
  -movflags +faststart \
  -f mp4 "$DST.part"

mv "$DST.part" "$DST"
```

Грабли, уже оплаченные:

- расширение `.part` не даёт ffmpeg угадать мукcер → **обязателен явный `-f mp4`**
- в zsh `0:a?` нужно **в кавычках**, иначе шелл съедает `?` как глоб
- таймкод у Sony лежит **на data-дорожке**, а не в `format_tags` — `format_tags=timecode`
  вернёт пусто, нужен `-select_streams d -show_entries stream_tags=timecode`
- `-colorspace/-color_primaries/-color_trc bt709` ставить **только** если источник не несёт
  тегов вовсе; на логе это враньё в метаданных
- клип-спаннер, живущий симлинком в двух сценах, кодировать **один раз**, вторую копию
  делать на Drive server-side

## 6. Правки в `make_proxies.py`

Файл: `scripts/999_extra/proxy_pipeline/make_proxies.py`

1. **Битность с источника.** Сейчас `--pix-fmt` / `--profile` — глобальные аргументы с
   дефолтом `p010le`/`main10`. Сделать значением по умолчанию `auto`: для каждого клипа
   читать `pix_fmt` источника и выбирать `main10/p010le` или `main/yuv420p`. Явно заданный
   аргумент перекрывает авто.
2. **Таймкод.** В `probe()` добавить чтение tmcd; в `encode()` — `-timecode` при наличии.
3. **Гейт расширить.** Сейчас проверяется только число кадров. Добавить: разрешение,
   `r_frame_rate` строкой (чтобы 30 ≠ 30000/1001), число аудиодорожек, число каналов в
   каждой, наличие TC если он был в источнике. Не сошлось → ретрай, второй раз не сошлось →
   клип НЕ уезжает и попадает в отчёт.
4. **Недекодируемый звук.** Перед кодированием проверять, что все аудиодорожки читаются;
   если нет — клип в список «copy as-is», не перекодировать.
5. **Отчёт.** В `proxy_report.json` писать по каждому клипу пару источник→прокси всех восьми
   параметров контракта, а не только кадры.

## 7. Гейт приёмки

Комплект принят, когда по **каждому** клипу:

- число кадров прокси == число кадров оригинала
- разрешение и `r_frame_rate` совпали строкой
- битность прокси соответствует битности источника по правилу §2.4
- число аудиодорожек и каналов в каждой совпало
- TC в прокси есть, если он был в источнике, и равен ему
- относительный путь и имя файла совпали 1:1
- размер прокси в 12–25 раз меньше оригинала (выход за коридор = повод посмотреть руками)

## 8. Ночной прогон: пересборка комплекта YTCH

**Объём.** Перекодировать надо только FX3. iPhone (34 клипа, 4.8 ГБ) копируется как есть и
уже лежит корректно.

| Проект | Клипов FX3 | Оригиналы | Прокси сейчас |
|---|---|---|---|
| YTCH10_Anya_Yulia | 151 | 492 ГБ | 27.5 ГБ |
| YTCH11_Liza_Vitalik | 92 | 332 ГБ | 18.5 ГБ |
| YTCH12_Sveta | 115 | 225 ГБ | 12.5 ГБ |
| YTCH13_Kirill_2 | 26 | 166 ГБ | 9.3 ГБ |
| YTCH14_Katya | 23 | 123 ГБ | 6.9 ГБ |
| **Итого по проектам** | **407** | **1337 ГБ** | **74.8 ГБ** |
| + Masha / Gulya (`_unassigned_footage`) | 21 | ~40 ГБ | 0.35 ГБ (2 клипа) |

**Время.** Кодирование ≈ **5.0 ч** (замер: YTCH14 = 123 ГБ за 27.2 мин при `--jobs 3`).
Заливка ≈ **13.8 ч** (замер этой сессии: ~1.5 МБ/с). Длинное плечо — заливка, не кодирование.

**Место — главный риск.** Свободно: T7-Beige **7.8 ГБ**, T7-Blue-2 17 ГБ, T9-Black 32 ГБ,
Macintosh HD **38 ГБ**. Комплект целиком (75 ГБ) не помещается никуда.

Схема — **поштучно, с перекрытием**, как в `footage_catalog/proxy_night.py`:

```
клип → кодировать в стейджинг → гейт → залить на Drive → удалить локально
```

- стейджинг на внутреннем диске: `/Users/romansergeev/YTAI_proxy_stage/`
- `--jobs 2`, не 3: пик места = число параллельных клипов × самый большой прокси
  (3.59 ГБ у `YTCH12/RYA-FX3-0890`, оригинал 63.5 ГБ) → пик ≈ 7.2 ГБ, влезает с запасом
- заливка отдельным потоком через очередь, чтобы не ждала конца кодирования
- заливать **на те же пути** на Drive (`YTCH S3/{проект}/01_Source_Proxy/...`) — файл
  заменяется, ID папок сохраняются, розданные монтажёру ссылки остаются живыми

**Запуск** (см. канон длинных прогонов — `nohup` + `caffeinate`, лог в `00_Setup/logs/`):

```bash
nohup caffeinate -is bash ~/YTAI/scripts/999_extra/proxy_pipeline/rebuild_ytch_10bit.sh \
  > /Volumes/T7-Beige-RYA/YTCH/_night_ops/logs/proxy_rebuild_$(date +%Y%m%d_%H%M).log 2>&1 &
```

Скрипт `rebuild_ytch_10bit.sh` ещё не написан — пишется вместе с правками §6.

**Риски и что с ними делать:**

- ⚠️ Заливка 75 ГБ **забивает аплинк почти на сутки** и душит любые скачивания с Drive.
  Ставить на время, когда канал не нужен; при необходимости — пауза.
- ⚠️ Монтажёру придётся **перекачать комплект** (75 ГБ). Предупредить до старта, не после.
- Диск T7-Beige на 100% — стейджинг только на внутренний, любое накопление на внешнем
  уронит прогон.
- Если прогон упадёт по середине: клипы, уже прошедшие гейт и залитые, повторно не
  кодируются (сверка по наличию на Drive + совпадению параметров).

**Порядок, если решим делать не всё сразу.** По убыванию пользы:
YTCH12 (в активном ревью) → YTCH11 → YTCH10 → YTCH14 → YTCH13 → Masha/Gulya.
