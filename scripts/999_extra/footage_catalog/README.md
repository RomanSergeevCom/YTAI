# Footage Catalog — HTML-каталог съёмочного материала

Этап стандарта: **после выгрузки исходников спринта на Drive** собираем одну
HTML-страницу-каталог всех съёмочных папок канала: у каждого видео — осмысленная
обложка (не случайный кадр), хронометраж, размер и прямая ссылка на файл в Google
Drive. Страница помогает потом *использовать* материал: найти сцену глазами, не
скачивая гигабайты. KB: https://yt.rya.ae/kb/footage-catalog/

Живой пример: YTFP → `YTFP_structure.html` в корне канала на Drive
(и `/Volumes/T7-Beige-RYA/YTFP/`).

## Конвейер (порядок запуска)

| # | скрипт | что делает |
|---|--------|-----------|
| 1 | `extract_frames.py` | обход локальных папок: ffprobe длительности + средний кадр каждого клипа (быстрый первый проход) → `local_meta.json`, `thumbs/` |
| 2 | `drive_thumbs.py` | для папок, которых нет на SSD: листинг через Drive API + готовые превью (`thumbnailLink`) → `drive_meta.json`, `thumbs_drive/` |
| 3 | `pick_frames.py local\|drive` | **выбор обложки**: 7 кандидатов на клип (12–88% длительности), локальный скоринг OpenCV — `3×лицо + резкость + 1.2×экспозиция + 0.5×цветность` → `cands/`, `chosen/`, `picked_*.json`. Drive-клипы читаются ffmpeg'ом по HTTP range (качаются килобайты, не файл) |
| 4 | (опц.) визуальный QC | агентный просмотр `chosen/*.jpg`, замены → `swaps.json` → `apply_swaps.py` |
| 5 | `fetch_ids.py` | карта `{папка_имяфайла: drive_file_id}` для прямых ссылок → `video_ids.json` |
| 6 | `gen_html_v2.py` | сборка страницы в стиле yt.rya.ae (тёмная, акцент канала, статусы SSD/Drive, ссылки на папки и файлы) → `{CH}_structure.html` |
| 7 | `link_refresher.sh` | если параллельно шла дозаливка папок на Drive: ждёт конца upload'а, пересобирает страницу с полными ссылками и перезаливает её (тот же file-ID → ссылка не меняется) |

Питон для `pick_frames.py` — `environment/.venv_transcribe` (нужен cv2); остальное — системный python3.

## Обязательный шаг: сверка SSD ↔ Drive

Перед публикацией сверить состав видео по **именам и размерам** в обе стороны
(см. inline-сниппет в KB-статье). Кейс YTFP 20.08.2026: папки 07 и 13 на Drive
оказались пустыми — 214 ГБ существовали только на SSD.

## Грабли

- Shared Drive: Drive API требует `supportsAllDrives=true&includeItemsFromAllDrives=true`, иначе пустой листинг.
- У «необработанных» видео на Drive нет `thumbnailLink` — тогда кадр тянуть ffmpeg'ом по HTTP range с Bearer-токеном (`~/.config/rscore/token.json`).
- HTML на Drive не рендерится в превью — получатель скачивает и открывает в браузере.
- Очень короткие клипы (~1 c): mjpeg-энкодер падает на non-full-range YUV → флаг `-strict unofficial`.
- Дубли имён клипов между папками реальны (напр. `RYA-ZVE1-1649.MP4` в 02 и 09) — все карты ключуются `NN_<rel>`, не именем файла.

## v1 hardcode

Скрипты v1 захардкожены под YTFP (пути, folder-ID, описания папок в `RU{}`).
Для нового канала: поменять `ROOT`, `DRIVE_IDS`, `RU`, тексты шапки в
`gen_html_v2.py`. Генерализация в CLI — при втором использовании.

## Развитие (задел)

- транскрипт-выжимка в карточку клипа (первая фраза / темы) из `Transcripts/per_clip`;
- VLM-описания сцен и экранов локальными моделями (mlx) — теги «кто в кадре / что происходит»;
- поиск по содержимому поверх каталога.
