## Что ещё считается нарушением (исправить)
1. **Таймкод только в начале строки или пункта.** «Добавить плашку на 3:08–3:11» → пункт «3:08–3:11 ▸ добавить плашку …».
   Таймкод в скобках внутри поясняющей фразы допустим только в строке-сводке, где он не место действия.
2. **Никаких перечислений в строку** через «→», «/», «|», «;», «vs», «·», запятые — если это отдельные пункты (шаги, варианты,
   подписи, страны, этикетки). Шаги процесса «A → B → C» — пунктами по порядку; варианты — «А ▸ …», «Б ▸ …».
   Исключение — дословная цитата экранного текста в «…», где «/» — перенос строки титра (можно так и оставить).
3. **Одна строка — одна мысль.** Две ошибки, два слоя, две задачи в одной строке через «;» — разнести.
4. **Обрывки** («линия уходит…», «так пишут только про…», «(калька с англ.») — восстановить полную мысль по полю
   `audit_findings_full` (там полные тексты находок аудита) или переформулировать коротко без обрыва.
5. **Внутренний жаргон** — убрать или заменить понятным: имена кадров «h0036», «s128», «f0061», «нота 049», «коммент 050»,
   «ночной разбор», «ревью №1», «(проверено зумом кадра f…)», «слой V5/V3» можно оставить только в блоке НА ТАЙМЛАЙНЕ.
   Секунды «166.0–168.6 с» → таймкоды «2:46–2:48».
6. **У каждого ТЗ есть ✅ СДЕЛАТЬ** — конкретное действие монтажёра. Если его нет — сформулируй из находки (без новых фактов).
7. **Противоречия внутри ТЗ** (диапазоны, числа, «готово»/«сделать», устаревшие ссылки на снятые ТЗ 08/09/29/40/42/43/45/47/49/51/52/58/62/69/70)
   — привести к согласию. Комментарий Романа (💬, поле roman_comment) главнее старого текста ТЗ: если он просит иначе — ✅ СДЕЛАТЬ
   переписать под него. Если для согласования нужен выбор заказчика — не выдумывай, верни предложение в `decisions`.
8. **Вопросы заказчику внутри текста** («Роман: отметь…») — убрать из parts, вернуть в `decisions` (я оформлю как ❓).
9. Для ТЗ-30/74/75/76 блок `list` НЕ писать — он генерируется из данных. У ТЗ-72/73 элемент с `"items": "@prog:08|09"` — оставить как есть.
