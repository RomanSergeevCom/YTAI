TL;DR

What's changing?

Current INGEST builder packs all clips back-to-back, losing real shooting chronology and capping at 2 cameras (V1+V2). The rewrite places clips on their wall-clock offset from scene_t0, supports N cameras (auto-detected from path), and places TX lavalier as continuous strips with sustained trim handles.

Problem: Why back-to-back placement isn't enough

S03 (Developer Meeting) shot over ~45 minutes of real time. DJI camera recorded in 20 separate clips with pauses. iPhone joined briefly mid-meeting for 5 clips. Throughout the whole 45 minutes, a lavalier mic on Vlad's chest recorded continuously — 27 minutes 31 seconds of audio.

Current behavior (back-to-back)

V1 DJI:    [DJI75][DJI76][DJI77]...[DJI94]   ← всё встык
V2 iPhone: ∅ (multicam.pairs не описаны)
A3 TX:     [TX][TX][TX]...[TX] [TX][TX][TX]  ← 18 кусков с дырами
        0s──────────────────────────────────150s
  • Реальные 45 минут схлопнуты в ~3 минуты compressed timeline
  • iPhone теряется (нет места в pair-схеме)
  • 27-минутный непрерывный TX разорван на 18 фрагментов
  • VO-материал из gap'ов потерян

Wall-clock layout (target)

  • Реальная хронология видна на таймлайне
  • iPhone на V2 в своём моменте (~34:40 от scene_t0)
  • TX непрерывной полосой 27:31 → VO-материал доступен
  • Trim handles на TX → можно расширить за scene boundary

Placement algorithm (conceptual)

for each scene:
  scene_t0 = min(creation_time for source in scene.clips ∪ tx_strips[scene])
  cam_layers = override OR auto_detect(scene.clips)

  seq = createSequence (empty) + applyMediaSettings (3840×2160@50fps, 48kHz)

  for video clip in scene.clips:
    v_idx = cam_layers[cam_from_path(clip.path)]
    offset_sec = clip.wall_offset
    createOverwriteItemAction(seq, clip.item, TickTime(offset_sec), v_idx, v_idx)

  for tx_strip in tx_strips[scene]:
    a_idx = max(cam_layers.values()) + 1 + tx_strip_index
    offset_sec = (tx_strip.creation_time - scene_t0).total_seconds()
    createOverwriteItemAction(seq, tx.item, TickTime(offset_sec), -1, a_idx)  // audio-only

Backward compatibility

JSON без layout_mode или с layout_mode: "linear" обрабатывается старым linearBuilder. Старые поля (offset, multicam.pairs, camera, dji_audio) остаются валидными для v1.x проектов (YTCR01, YTCR02).

Layering rules (enforced by code review)
  1. layout/* — pure JS, никаких imports из premierepro. Unit-тестируется Node-юнитами.
  2. placement/* — может импортировать premierepro, использует layout/*. Не наоборот.
  3. timelineBuilder.js — public API. Re-exports findProjectItemByName, applyMediaSettings для back-compat с transcriptImporter.js:13.

TX Path B+ strategy

Bin vs sequence (the key insight)

PROJECT BIN:                          SEQUENCE TIMELINE:
├── 00_Source                         (scene-bounded TrackItems)
│   └── 03_developer_meeting
│       ├── DJI_..._0075_D.MP4
│       ├── DJI_..._0076_D.MP4              0s              ...        2655s
│       └── ... (25 clips)                  ├───────────────────────────┤
└── TX_Strips                          V1:  [DJI75]  [76][77]  ░ [93][94]
    └── TX00_MIC044_..._orig.wav       V2:                  [iPhone clips]
         (FULL 1651s ProjectItem)      A3:  [━━━━━━━━━━━━━━━━━━━━━━━━]
                                                                      ↑
                                              TrackItem scene-bounded,
                                              source still full,
                                              trim handles available

ProjectItem in bin = always full source. A TrackItem in the sequence is an instance with its own in and out points (sub-range). Trimming a TrackItem (drag edges) doesn't modify the ProjectItem. Editor can extend trim at any time to reveal more of the original recording.

Filename pattern: TX{NN}_MIC{NNN}_{YYYYMMDD}_{HHMMSS}_orig.wav — datetime in local Dubai TZ (UTC+4). Python 0112_collect_tx_strips.py parses this, converts to UTC, validates sample_rate, maps to scenes by time overlap.

Glossary

scene_t0Earliest creation_time across all clips/TX in a scene. Zero-point of local timeline.
wall_offsetSeconds between clip's creation_time and scene_t0. Always ≥ 0.
V-track / A-trackPremiere sequence tracks. V1 = videoTrackIndex 0.
TXTransmitter — беспроводной передатчик микрофона-петлички.
Lavalier (петличка)Микрофон-клипса на одежде, подключенный к TX.
BWF / bextBroadcast Wave Format extension. bext.timeReference хранит время начала записи в samples.
ProjectItemPremiere bin entry. Full source.
TrackItemSequence instance of ProjectItem с in/out points.
Trim handlesDrag edges of TrackItem в timeline → расширить без re-import.
createOverwriteItemActionUXP API: положить ProjectItem на позицию, перезаписывая существующее (не shift other tracks).
TickTimeUXP class. ppro.TickTime.createWithSeconds(s).
lockedAccess + executeTransactionUXP wrapper для thread-safe project modification.
Path ATX как per-clip куски на позиции видеоклипов. Legacy mode.
Path B+TX как unsplit полоса scene-bounded с trim handles. Wall-clock mode.
