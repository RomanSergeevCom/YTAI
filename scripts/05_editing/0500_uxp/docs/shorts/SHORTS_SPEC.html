01

Архитектура: Claude — мозг, панель — руки, HTML — витрина

Никакого LLM внутри панели. Тот же проверенный паттерн, что и в Assembly-цикле (_in.json / _out.json), — только своя папка, своя схема и свой builder. Ни у одного конкурента такого round-trip нет.

Мозг · Claude Code (чат)

Поиск и скоринг

  • читает пословные транскрипты + vision-индекс
  • ищет моменты, скорит (Hook/Flow/Value/Emotion)
  • режет по словам с «воздухом», снап к кадру
  • пишет _v{N}_in.json + HTML-витрину
→
Руки · UXP-вкладка Shorts

Превью и сборка

  • список кандидатов, статусы ✓/✗
  • preview-секвенция с range-маркерами
  • read-back правок (маркеры двигал юзер)
  • build 9:16 на тиках + verify-гейт 2 мс
→
Результат · Premiere

Секвенции в бине Shorts

  • {CODE}_S{NN}_{slug} 1080×1920
  • опция: дубль 16:9
  • маркеры-метаданные (score, src tc)
  • экспорт мастеров → шортс-папка проекта
↩
Кнопка Out → Claude: панель пишет _v{N}_out.json (статусы, правки маркеров, отчёт сборки, issues[]) и кладёт путь в клипборд → вставляешь в чат → Claude улучшает → _v{N+1}_in.json с changelog → Refresh в панели.
02

Два режима работы

Сначала — из готовых видео (проще и быстрее к результату), потом — сразу после инжеста.

MODE A · finished MVP-1

Из готового видео

Режем сам финальный рендер по его собственному пословному транскрипту. Маппинг на камерные исходники не нужен — качество уже запечено в рендер.

вход:
· 02_Exports/YTCR1_v16_Arty_Dzis.mp4 (31:13)
· 00_Setup/05_Review/v16/YTCR01_v16_pass2.json
  979 сегментов, words[{word,start,end}], EN

Для будущих проектов: шаг «transcribe final export» (mlx, минуты) — уже делаем ad-hoc для QC, закрепляем как стандартный пре-шаг.

MODE B · ingest MVP-3

После инжеста

Кандидаты из исходников: может быть многоблочным — hook из середины + тело из другого клипа (hook-first reorder, самая недообслуженная фича рынка).

вход:
· Transcription/…_transcript_assembly.json
· per_clip/<scene>/C####.words.json + _en.json
· 06_Enrichment/full_source_index.json
  vision-каталог 1129 клипов: energy, emotion,
  live_score, best_tc → сигнал скоринга + B-roll
⚠️ Грабли данных

Конкатенированные SRT (_transcript.srt, _wordlevel.srt) сбрасывают таймкод на границах сцен — в finder не подавать. Только per-clip/scene JSON.

1

Source — авторезолв

Проект уже выбран глобально. Панель сканирует 00_Setup/07_Shorts/ на свежайший _in.json, режим берёт из JSON.

2

Candidates — демонстрация

Карточка: чекбокс-approve, скор с именованными факторами + строка «почему» (не голая цифра — им не доверяют), длительность, hook-цитата, jump-to. В Premiere ещё ничего не пишется.

3

Preview — коррекция в таймлайне

Секвенция «рендер + range-маркер на каждого кандидата». Границы правишь перетаскиванием маркеров — родными инструментами Premiere. Read Back забирает правки в state. Пересечения кандидатов — блокирующий гейт.

4

Build — сборка выбранных

Секвенция на шорт, 1080×1920, блоки overwrite-ом на тиковой сетке, последовательные транзакции. После сборки — verify-гейт: read-back дампом, толеранс 2 мс, результат в панель и в _out.json.

5

Exchange — round-trip

Out → Claude: пишет _out.json, путь в клипборд. HTML-витрина открывается в браузере — кандидатов можно смотреть плеером ещё до открытия Premiere.

04

Файлы и контракт данных

Всё живёт в 00_Setup/07_Shorts/ (следующий номер после 06_Enrichment). Версии никогда не переписываются — новая генерация = v{N+1}.

Структура

{project}/00_Setup/07_Shorts/
├── YTCR01_Shorts_v1_in.json ← Claude → панель
├── YTCR01_Shorts_v1_out.json ← панель → Claude

Что внутри _out.json — «состояние + баги»

05

Канон точности — слова не режутся в ноль

У всех конкурентов границы «примерные» (сами документируют: «подвинь маркер, если криво»). Наш канон — пословный, с воздухом и числовой верификацией.

Воздух — никогда в ноль

pad_head = min(gap, 250ms)
pad_tail = min(gap, 300ms)
gap=0 (слова впритык) → pad=0, чужое слово не захватываем; но тогда Claude обязан рассмотреть сдвиг границы на фразу.

Позиции — только тиками

TickTime.createWithTicks, последовательные транзакции по возрастанию. Никаких float-секунд (double 109.44 → +1 кадр — проверено) и никаких compound overwrite (исполняются в обратном порядке).

Верификация числом

После сборки — read-back дампом секвенции, сверка с планом, толеранс 2 мс. Не прошло → issue B02, секвенция помечена. Не «на глаз», а как в wordsync-канонe.

06

Скоринг-рубрика (Claude-side)

ФакторЧто меряет
Hookпервые 3 секунды останавливают скролл: вопрос, цифра, провокация, незавершённость
Flowзаконченная мысль: началась и закрылась, никакого mid-sentence; арка внутри 20–59 с
Valueпольза / инсайт / цитируемость
Emotionпики: смех, злость, уязвимость; в ingest-режиме += energy/emotion/live_score из vision-индекса

Правила выдачи

  • · 8–15 кандидатов на видео — больше нет смысла (рынок: ~40% брак даже у топов)
  • · обязательное поле why — одна строка на человеческом
  • · длительность default 30–59 с, таргет из канала
  • · hook-first reorder разрешён (blocks с ролями), но прямой вариант всегда рядом
  • · скор = порядок сортировки, не вердикт; ворота — человек
07

Reframe 9:16 и титры

Reframe

MVP: mode:"static" — 4K-кадр в секвенции 1080×1920 со статичным сдвигом по crop_center_x_pct (Claude оценивает по кадрам — face_finder/vision локально). Позже: кейфреймы по треку лица.

⚠️ Спайк S-1 — единственный технический блокер этой части

Умеет ли UXP 25.6/26.0 ставить Motion Position/Scale (ComponentParam.createSetValueAction)? В кодовой базе прецедента нет, а VideoClipTrackItem.cast в 26.0 сломан. Fallback-и готовы: (a) кнопка Premiere Auto Reframe на построенной секвенции — так делает Firecut; (b) офлайн ffmpeg-crop по треку лица — путь «шорт вообще без Premiere» для батчей.

Титры

Claude пишет per-short SRT (от нуля, из words[], фразы 1–4 слова, с тем же воздухом) → 07_Shorts/srt/.

MVP — файл рядом, импорт руками/позже кнопкой. Burn-in стили (MOGRT/Essential Graphics) — вне MVP, отдельная история.

HTML-витрина

Карточка кандидата = кнопка «play range»: встроенный плеер file:// на рендер v16 играет ровно диапазон шорта. Смотреть и выбирать можно до открытия Premiere. Со v2 — changelog и CHANGED-бейджи.
