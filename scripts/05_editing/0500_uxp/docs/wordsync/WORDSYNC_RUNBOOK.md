# WORDSYNC RUNBOOK — сборка мультикам-таймлайна по пословным транскриптам

**Для кого:** любая модель/оператор, выполняющий сборку мультикам-дня в UXP-таймлайн.
Ранбук самодостаточен: выполняй шаги по порядку, после каждого шага — **ГЕЙТ**
(проверка). Не переходи к следующему шагу, пока гейт не зелёный. Если гейт красный —
раздел «Триаж» в конце шага.

**Что делает система:** клипы N камер + куски петлички/рекордера ложатся на один
таймлайн Premiere в синхроне, используя **речь** (пословные транскрипты) вместо часов
устройств. Часы устройств ВРУТ (проверено: кварц ±5–22 мин, имена файлов рекордера
±9.5 мин, у одной камеры стоял другой год) — никогда не собирай мультикам по
creation_time без речевой проверки.

**Инструменты** (все в `~/YTAI/scripts/999_extra/wordsync_multicam/`):

| Скрипт | Роль |
|---|---|
| `wordsync.py` | решает синхрон дня (граф часов) → `wordsync_result.json` |
| `make_ingest.py` | результат → v2.0 wallclock ingest + симлинк-раскладка камер |
| `validate_ingest.py` | проверяет ingest на ВСЕ требования UXP-билдера |
| `qc_html.py` | тёмная QC-витрина для проверки глазами |

Теория и принцип: `wordsync_multicam_README.md` рядом со скриптами и
KB-страница `yt.rya.ae/kb/multicam-wordsync/`.

## Шаг 0. Предпосылки

Собери факты о дне (папка вида `/Volumes/DISK/{CHANNEL}-YYYYMMDD/`):

```bash
DAY=/Volumes/DISK/XXX-20260704       # папка съёмочного дня
ls "$DAY"                             # камеры: папки CAM*; петля: Sound/*.WAV
find "$DAY" -name "*.words.json" | wc -l   # транскрипты есть?
```

Нужно ЗАРАНЕЕ знать/решить:
1. **Список камер** и их роли → порядок дорожек V1..VN (V1 = основная).
2. **Есть ли петличка/рекордер** (`Sound/*.WAV` с временем в имени `*_YYYYMMDD_HHMMSS`)
   → режим A (lav). Нет → режим B (`--ref-cam`, опорная камера).
3. **Сцена** — имя секвенции, напр. `04_Studio`, `05_Interview`.
4. **Проект** — папка `{PROJECT}` с `00_Setup/01_Ingest/`.

### ГЕЙТ 0
- [ ] У КАЖДОГО видеоклипа и КАЖДОГО куска петли есть `{stem}.words.json`
      под `{DAY}/Transcription/` (иначе — сначала транскрибация, см. pipeline).
- [ ] `ffprobe` любого клипа каждой камеры показывает непустой `creation_time`.
- [ ] Ты знаешь порядок камер V1..VN (спроси у Романа, если не сказано; для YTUVI
      канон: V1 = Vostorg B основная, V2 = A верхняя/руки, V3 = C детали, V4 = FX3).

**Триаж:** нет транскриптов → это блокер, транскрибируй (mlx_whisper, пословный
формат); нет creation_time (после re-wrap) → клипы с речью всё равно лягут
(`speech_unrefit`), немые — нет.

## Шаг 2. Решение синхрона дня

### Режим A — есть петличка (Sound/*.WAV)

```bash
python3 wordsync.py --day "$DAY" \
  --cam-map "CAM1=CAM1_VostorgB,CAM2=CAM2_VostorgA,..."   # папка=имя_камеры
```

### Режим B — петли нет, 2+ камеры со звуком

```bash
# опорная камера = та, что писала дольше/стабильнее (обычно главная).
# --only-file: стемы клипов, которые нужно ПОЛОЖИТЬ на таймлайн (по одному на строку).
# Якорями работают ВСЕ транскрипты опорной камеры, не только выбранные.
python3 wordsync.py --day "$DAY" --ref-cam CAM1-FX3A --only-file selected.txt
```

Результат: `{DAY}/Transcription/_wordsync/wordsync_result.json` + отчёт в stdout.

### ГЕЙТ 2 — читать ОТЧЁТ, не только exit code
- [ ] `edges kept` ≥ (число клипов с речью) × 1 примерно; `dropped as outliers`
      — малое число (0–3). Сотни dropped = данные перепутаны.
- [ ] **Резидуалы**: в таблице клипов `resid` < 1с у всех speech-клипов
      (типично 0.0–0.6с). Один большой резидуал = клип пришит к чужому дублю →
      триаж. `max|resid|` по камере тоже < 1с.
- [ ] **Δ камер осмысленные**: у каждой камеры одно стабильное Δ. Если Δ дикое
      (часы/дни) — проверь creation_time этой камеры (бывает другой ГОД).
- [ ] **Непрерывность сплитов** (режим A): рекордер режет файлы встык — пары
      `gap` у таких соседей должны быть ~0 (|gap| < 0.2с). Это контроль истиной:
      большой зазор на сплит-паре = решение НЕВЕРНО, не продолжать.
- [ ] **Поправки имён** (режим A): `correction` кусков — либо ~0, либо явный
      флаг `FILENAME WRONG` у меньшинства. Если "врут" ВСЕ куски — рамка
      сорвалась, триаж.
- [ ] Клипы `clock`-fallback объяснимы (немые/в дырах петли), их немного.
- [ ] `UNPLACED` — ноль, либо ты понимаешь каждый (нет ни речи, ни ct).

**Триаж:**
- Большой резидуал у одного клипа → короткий сценарный клип пришился к дублю.
  Проверь глазами в QC (шаг 5) первые слова матча; в крайнем случае убери клип
  из выборки и положи руками в Premiere.
- Все камеры «прыгают» на одну величину в части дня → врут имена кусков
  (это нормально, решение чинит) — убедись, что флаги FILENAME WRONG стоят.
- `ambiguous transcript stem` → два файла с одинаковым стемом; зеркаль структуру
  дня в Transcription/ (скрипт откажется гадать — это защита).

## Шаг 3. Ingest: мультикам-сцена

```bash
P=/Volumes/DISK/{CHANNEL}-Projects/{PROJECT}
python3 make_ingest.py --project "$P" --scene 04_Studio --add \
  --result "$DAY/Transcription/_wordsync/wordsync_result.json" \
  --cam-order "CAM1_VostorgB,CAM2_VostorgA,CAM3_VostorgC,CAM4_FX3"  # = V1..V4
```

Что произойдёт: симлинки `01_Source/{scene}/{CAM}/*.MP4` (файлы НЕ
копируются; сцена-папка лежит прямо в 01_Source, без обёрток Video/Audio —
одна папка = один таймлайн), петля → `01_Source/{scene}/{TX}/`, ingest →
`00_Setup/01_Ingest/{CODE}_ingest.json` (старый уходит в `*_backup_*.json`).
`--add` = merge: другие сцены в ingest не трогаются.

Линейная сцена (selects/b-roll, одна дорожка, встык):

```bash
python3 make_ingest.py --project "$P" --scene 06_Retail --add \
  --linear --files-from retail.txt --folder RETAIL     # retail.txt: пути, по строке
```

### ГЕЙТ 3
- [ ] Вывод: число клипов/tx совпадает с ожиданием; `t0` осмысленный.
- [ ] Коллизии имён: скрипт сам переименовывает в linear-режиме
      (`FOLDER_name.mp4`) и ПАДАЕТ в sync-режиме — падение = стоп, разберись.
- [ ] Симлинки смотрят куда надо: `readlink` 2–3 штук.

**Правила, которые НЕЛЬЗЯ нарушать** (билдер откажет ТИХО):
- имена камер в `--cam-order` = байт-в-байт имена папок-родителей клипов;
- пути в ingest = пути симлинков, никогда не `realpath`;
- у ingest всегда `version:"2.0"` + `layout_mode:"wallclock"` + `files:{}`;
- `tx.sample_rate` == `media.sample_rate` (иначе петля молча выпадет);
- имена файлов уникальны глобально (билдер резолвит клипы ПО ИМЕНИ).

## Шаг 4.5. Точный синхрон по звуку (finesync)

Речевой синхрон ставит день на общую ось с точностью **0.6–0.9 с** (15–20 кадров).
Этот шаг доводит её до **единиц миллисекунд** — после него по петличке можно резать
как по основной дороге диалога. Работает ТОЛЬКО здесь: до Build, после ингеста.
Правит `wall_offset` в ingest, билдер дальше пересобирает всё сам.

**Из панели (основной путь):** вкладка Ingest → в сводке видно
`Fine sync: NOT APPLIED` → кнопка **Fine Sync** (Терминал откроется сам) → панель
дождётся, перечитает ingest и напишет «REBUILD the sequences» → **Build Ingest**.

Из терминала — то же самое:

```bash
cd ~/YTAI/scripts/999_extra/audio_finesync
python3 finesync_run.py "$P"            # посмотреть (~1.5 мин на съёмочный день)
python3 finesync_run.py "$P" --apply    # применить + валидатор + ПЕРЕМЕР + вердикт
```

Отчёты: `$P/00_Setup/01_Ingest/finesync/`. Откат: `*_backup_finesync_*.json` рядом
с ingest. Premiere закрывать не нужно — проект не трогается, только JSON и чтение медиа.

### ГЕЙТ 4.5
- [ ] Вердикт «Попадание точное»: все пары в допуске (полкадра).
- [ ] Невязка по сценам — единицы миллисекунд. Десятки = разбираться, не строить.
- [ ] Флаги **МОСТЫ** прочитаны: домерено `--repeat 3` или осознанно принято.
- [ ] Флаг **распадается на N кусков** прочитан: внутри куска точность мс, между
      кусками осталась речевая — знать, где именно, и глянуть стык на Шаге 6.
- [ ] Если ingest уже строился в Premiere — секвенции ПЕРЕСОБРАТЬ, поправки в
      готовый таймлайн сами не приедут.

Теория и таблица флагов: `~/YTAI/scripts/999_extra/audio_finesync/README.md`.

## Шаг 4.6. Frame-align: перенос ms-точности в медиа (0113)

**Зачем (измерено на YTCH10+YTCH13, 16.08.2026):** у clip-API Premiere НЕТ
субкадрового рычага — `setSourceInOut` FLOOR'ит source in/out к кадровой сетке,
а позиция вставки (insert) ОКРУГЛЯЕТСЯ К БЛИЖАЙШЕМУ кадру (28/28 замеров по
тикам). Значит поправки fine-sync (субкадровые, у каждого клипа свои) при
раскладке оригинальных WAV теряются: остаточная ошибка до ±полкадра (±20 мс
@25p) и у каждого слайса РАЗНАЯ. Единственный сэмпл-точный рычаг — сама медиа.

Этот шаг рендерит на каждую (сцену × петличку) один WAV в координатах
таймлайна: контент каждого слайса лежит в файле ровно на том сэмпле, где
слайс встанет на таймлайн. Билдер кладёт identity-слайсы (offset == source-in,
точными тиками кадра) — Premiere нечего округлять, синхрон ≤ 1 сэмпла.

```bash
cd ~/YTAI/scripts/999_extra/wordsync_multicam
python3 0113_frame_align.py --project "$P" --dry-run   # посмотреть
python3 0113_frame_align.py --project "$P"             # рендер + патч ingest
```

Оригинальные строки петличек сохраняются в `tx_strips_source` ingest'а
(бэкап `*_backup_framealign_*` рядом); повторный запуск идемпотентен.

### ГЕЙТ 4.6
- [ ] `VERIFY OK: all placements on exact frame ticks` в конце вывода.
- [ ] «coverage gap» предупреждения прочитаны (файл рекордера кончился раньше
      блока видео — там тишина; десятки мс на стыках 30-мин файлов — норма).
- [ ] Если секвенции уже строились — ПЕРЕСОБРАТЬ (Build Ingest), как после 4.5.

## Шаг 6. Build в Premiere (руками Романа или по его «go»)

1. Premiere ≥ 25.6 → открыть `{PROJECT}.prproj`.
2. UXP Developer Tool → панель «YTAI Assembly» (id `com.ytai.assembly.panel`).
3. Вкладка **Ingest** → панель сама найдёт `{CODE}_ingest.json` → **Build Ingest**.
4. Получится по секвенции на сцену: `{CODE}_{scene}`, V1..VN + A1..AN (звук
   каждой камеры на дорожке с номером её V) + петля на A(N+1) полосами под видео.

### ГЕЙТ 6 — проверка синхрона ушами/глазами
- [ ] В 3 случайных точках включить A-дорожки двух камер одновременно —
      двойного «эха» нет (расхождение < кадра слышно как фленджер, > кадра — эхо).
- [ ] Хлопок/стук в кадре совпадает на всех углах.
- [ ] Петля (A5) совпадает со звуком камер.
- [ ] Мелкая докрутка при желании: панель `Offset` / `Sync Audio`.

### ГЕЙТ 6.5 — верификация синхрона ЧИСЛОМ (обязательный)

Уши ловят эхо от ~1 кадра; всё, что меньше, ловит только сверка тиков.
Панель → **Debug Dump** (пишет `99_Pipeline/logs/{slug}_dump_*/`), затем:

```bash
cd ~/YTAI/scripts/999_extra/wordsync_multicam
python3 verify_build_sync.py --dump "$P/99_Pipeline/logs/<свежий дамп>"
```

Скрипт пересчитывает план тем же кодом, что и билдер (tools/plan_cli.js), и
сверяет С КАЖДЫМ элементом таймлайна: счётчики по трекам, позиции, source-in,
длительности — всё в тиках, допуск 2 мс.

- [ ] `PASS` — иначе НЕ отдавать проект дальше. FAIL ловит ровно те дефекты,
      что 16.08.2026 прошли молча: съехавший на кадр overwrite, съеденную
      голову клипа, «вставленные», но отсутствующие TX-слайсы, недоудалённый
      seed-плейсхолдер.
- [ ] Предупреждение «media not frame-aligned» = Шаг 4.6 пропущен → петля
      с точностью ≤ полкадра, а не ≤ сэмпла. Решить осознанно или прогнать 0113.

**Триаж:** одна камера целиком съехала на константу → проверь, что build взял
свежий ingest (перезагрузи панель); клип красный (Media Offline) → Doctor →
«Find & Relink local» (симлинки живы, это кэш путей Premiere).
**Известная грабля (панель < v2.2.6):** в начале ВЕРХНЕЙ V-дорожки (и её
A-дорожки) может остаться обрезок ЧУЖОГО клипа длиной ровно до первого клипа
этой камеры — это неудалённый placeholder пре-варминга дорожек (getTrackItems
был не-await'нут и зачистка тихо не работала). Лечение: панель ≥ v2.2.6 +
Rebuild; или просто удалить этот обрезок руками (сверху V и его аудио).

## Частые ошибки исполнителя (сводка)

1. Собрать по creation_time «потому что похоже на правду» — НЕТ. Часы врут.
2. `realpath`/`resolve()` на путях клипов — камера потеряется (camFromPath).
3. Забыть `files:{}` или `layout_mode` — билдер тихо уйдёт в linear без петли.
4. Дать `--cam-order` с именами, не равными папкам, — клипы «unknown_cam» и тихо
   выпадут.
5. Не прочитать отчёт wordsync (только exit code) — резидуалы и сплит-пары
   это и есть доказательство синхрона.
6. Править `{CODE}_ingest.json` руками — только через make_ingest (merge/backup
   сломаешь).
